# 要件定義

- 承認：2026-11-26（TASK-P05）。正本は Notion の工程別ドキュメント「01 要件定義」で、作者が承認した版をこのファイルにした
- レビュー：TASK-R01
- 直すときは Notion を直し、承認を受けてからこのファイルも出し直す（`docs/rules.md` の「7.」）

## 1. 目的

- 資格の勉強で、自分のメモや試験の過去問から AI が問題を作り、解答の履歴から弱点を復習できるようにする
- 試験日から逆算した学習計画（階層 Todo・1日のノルマ）と進み具合の管理を、問題演習と同じアプリでできるようにする
- NotebookLM などのメモ・AI 系サービスとの違い：試験日までの計画と進捗管理が一体になっている

## 2. 対象ユーザーと使う場面

| 対象 | 使う場面 |
|---|---|
| 資格取得を目指すエンジニア（まずは作者が毎日使う） | 資格と試験日を登録する。AI が作った章・タスクのひな形を直して使う。毎日ノルマを見て進め、学んだことをメモする。メモや過去問から問題を作って解き、間違えたところを復習する |
| アプリを試しに触る人 | Google アカウントなしでゲストとして、サンプルデータ入りで全機能を試す |

Google アカウントがあれば誰でも使える。費用は回数制限（F-14）で抑え、自分のアカウントとデータは退会（F-15）で消せる。

## 3. 機能要件（MVP）

| ID | 機能 | 内容 |
|---|---|---|
| F-01 | ログイン・ログアウト | Google アカウントでログインする（パスワードは使わない）。初回ログインでユーザーを登録する |
| F-02 | ゲストモード | Google アカウントなしで、サンプルデータ入りで全機能を試せる。AI 生成は F-14 のゲストの上限まで。ゲストのデータは一定時間で消える（時間と仕組みは TASK-P13）。ゲストのデータをログイン後に引き継ぐ機能は作らない |
| F-03 | 資格の管理 | 資格を登録・編集・削除する（名前、試験日）。複数の資格を持てて、切り替えられる |
| F-04 | 章・タスクのひな形 | 資格を登録するときに、AI が公式サイトの出題範囲（試験ガイド・シラバスなど）を調べ、章とタスクのひな形を作る。参考にしたページのリンクを表示する。ひな形は保存する前に直せる。使わずに自分で作ってもよい。公式の情報が見つからないときはそう表示し、公式ページの本文を貼り付けて作ることもできる |
| F-05 | 階層 Todo | 資格＞章＞タスク（階層の数は TASK-P07）。追加・編集・削除・並べ替え・完了チェック。削除したときに配下をどうするかは基本設計で決める |
| F-06 | 試験日カウントダウン | 試験日まであと何日かを表示する |
| F-07 | 1日のノルマ | 未完了のタスク数 ÷ 試験日までの残り日数（切り上げ）を「今日のノルマ」として表示する。試験日を過ぎたら表示しない |
| F-08 | Markdown メモ | メモを書く・編集する・削除する。プレビューを見ながら書ける。紐付け先（章かタスクか）は TASK-P07 |
| F-09 | AI 問題生成 | 問題の形式は多肢選択・○×・穴埋め。作り方は2つ。(1) メモを選んで、その内容から作る。(2) 章（単元）を選ぶと、AI がその単元の過去問をウェブで探し、それを参考に新しい問題を作る。(2) で使うのは公式に公開されている過去問・サンプル問題だけで、非公式の問題集サイトは使わない。過去問はそのまま載せず新しい問題として作り、参考にした出典を表示する。過去問を公開していない試験では、(2) が使えないことを表示する。生成数などの細かい仕様は基本設計で決める |
| F-10 | 解答・採点 | 問題を解き、正誤と解説を表示する。解答の履歴を残す |
| F-11 | 弱点の復習 | メモや章ごとに、間違えた問題だけをもう一度解ける。資格全体から苦手な問題を混ぜて出す「弱点シャッフル」は2月以降 |
| F-12 | 進捗ダッシュボード | 資格ごとの進捗（タスクの完了率など）、カウントダウン、今日のノルマを1画面で見られる。進捗の計算式は基本設計で決める |
| F-13 | 学習カレンダー | 何日にどのくらい学習したかを、GitHub の草のようなマス目で表示する。1日の学習量は、その日に完了したタスクの数と解いた問題の数の合計（メモの編集は数えない） |
| F-14 | AI 生成の回数制限 | 章・タスクのひな形づくり（F-04）と問題生成（F-09）を数える。1人1日の上限と、全体の1日の上限を設ける。暫定値はログイン 1人1日10回、ゲスト 1日3回、全体 1日100回。ウェブ検索には1回ごとの料金がかかるので、それも含めて TASK-P09 の費用見積もりで数値を確定する |
| F-15 | 退会 | ユーザーが自分のアカウントと学習データをすべて削除できる（確認してから削除する。元には戻せない） |

## 4. MVP に入れないもの

- 2月以降：AI 要約（＋サンプルコード生成）、弱点シャッフル
- 後回し：解説チャット、合格可能性判定、資格テンプレート（よく使う資格のひな形をあらかじめ用意しておくもの。MVP では F-04 で AI がその都度作る）、集中時間トラッカー、テスト結果の手動記録

## 5. 非機能要件

| 項目 | 要件 |
|---|---|
| 費用 | 月600〜1,500円を目標にする。置いておくだけで課金される部品は使わない。AWS Budgets と Claude Console の月額上限を設定する。人が使っていないときに DB が起きないようにする（トップ・ログイン画面は DB を使わない、クローラーに DB を使うページを回らせない、DB の最大 ACU を低く抑える）。仕組みは TASK-P06 と基本設計で決める |
| セキュリティ | ログインは Google のみ。通信は HTTPS のみ。ユーザーは自分のデータだけ見られる・変えられる。API キーなどの秘密情報はコード・Git に置かない |
| 個人情報 | 保存するのは Google の名前・メールアドレス・ユーザー ID と学習データだけ。簡単なプライバシーポリシーのページを置く |
| 著作権 | 過去問・公式サイトの文章はそのまま保存・表示しない。AI が作った問題とひな形には、参考にした出典を表示する |
| 可用性 | 常に起きている必要はない。DB が止まっているときは再開（普通は約15秒、24時間以上止まっていると30秒以上）を自動で再試行し、画面に「起動中」と表示する |
| 障害への強さ | AI やウェブ検索が使えないときも、メモ・Todo・解答履歴は使える |
| 応答 | AI の生成を待つ間はスピナーなどで進み具合を示す。生成の目標時間と、同期か非同期ジョブかは TASK-E02 で決める |
| 動作環境 | PC・スマホ・タブレットの画面幅に対応する。ブラウザは最新の Chrome・Edge・Safari |
| 品質 | 自動テスト（Vitest・Playwright）と CI（lint・型チェック・テスト）を通してからマージする |
| 運用 | ログは CloudWatch で見る。エラーの通知が必要かは基本設計で決める |

## 6. 制約

- 技術構成：Next.js（App Router）＋TypeScript、Amplify Hosting、Aurora Serverless v2（PostgreSQL）＋Data API、Better Auth、Claude API。詳細と理由は ADR（TASK-P06）
- 作者1人で開発・運用する。2027年1月上旬に MVP を公開する
- ソースコードは公開リポジトリに置く
