# AI の使い方の記録

Studai は Claude を役割ごとに分けて開発しています。このファイルには、AI に任せたことと、自分で判断したことをタスクごとに残します。

## 役割分担（2026-11-20 時点）

| 役割 | 担当 | 設定 |
|------|------|------|
| PM・デザイナー・レビュー | claude.ai のプロジェクト | 指示文はローカルの docs/private/ に保管（非公開） |
| エンジニア（実装） | Claude Code | [CLAUDE.md](../CLAUDE.md)、[.claude/settings.json](../.claude/settings.json) |
| PR 前のレビュー | Claude Code の reviewer サブエージェント | [.claude/agents/reviewer.md](../.claude/agents/reviewer.md) |

- 実装した AI に自分で採点させないよう、レビューは別の文脈（サブエージェント、別のプロジェクト）で行う
- AI が書いたコードは、自分で説明できるようになってから取り込む
- 秘密情報の読み取り禁止や push 前の確認は、指示文ではなく権限設定（settings.json）で強制する

### TASK-P17 — push・PR・マージの進め方の変更（2026-11-26）
- AI に任せたこと：運用ルール（rules.md）と CLAUDE.md の書き換えの下書き（PM）、ファイルの置き換えと、rules.md・CLAUDE.md・reviewer サブエージェントの指示の食い違いの確認（Claude Code）
- 自分で判断したこと：どの役割も自分のタスクの作業用ブランチへの push と develop 宛ての PR の作成を、作者の承認なしに行ってよい／PR は必ずレビューが確認し、OK を出したレビューがマージする（PR を作った役割は自分でマージしない）／Claude Code の権限設定（settings.json）から push と PR 作成の確認を外し、マージの確認は残す（設定は自分で直した）
- 理由：push と PR の作成のたびに作者の承認を挟まずに進められるようにしつつ、develop に入る前には必ず別の役割のレビューを通すため

### TASK-H01 — 技術構成を理解する（Amplify Hosting・Aurora Serverless v2・Data API）（2026-11-26）
- AI に任せたこと：Amplify Hosting と Aurora Serverless v2・Data API の解説（仕組み、他の選択肢との違い、費用の目安）、作者のまとめの確認、学習メモのコミット
- 自分で判断したこと：解説を受けて、自分の言葉でまとめた（学習メモの「作者のまとめ」）。秘密情報の置き場所は TASK-P06、ORM か SQL を直接書くかは TASK-P08 で決める
- 理由：技術構成は引き継いだ決定なので、自分で説明できるようになってから ADR を作り直すため

### TASK-P16 — 認証ライブラリの変更（Better Auth）（2026-11-25）
- AI に任せたこと：Auth.js・Better Auth・Cognito の比較と解説、反映するファイルの洗い出し
- 自分で判断したこと：認証ライブラリを Better Auth にする／セッションは JWT 方式
- 理由：Auth.js は保守だけの状態になっていて、開発が続いている Better Auth に切り替えるほうが安全なため。JWT 方式なら、ログインの確認のたびに Aurora を見に行かずに済み、費用がかさまないため

### TASK-P15 — 工程ごとの資料の置き場所とマージ前の手順（2026-11-25）
- AI に任せたこと：工程ごとの資料の置き場所の案、運用ルール（rules.md）・CLAUDE.md・ひな形の書き換え、3つのファイルの食い違いの確認
- 自分で判断したこと：資料を工程ごとに Notion とリポジトリの両方に残し、正本を工程で分ける（設計は Notion、実装とテストはリポジトリ、画面と ADR はファイル）／マージ前に progress.md を完了にする手順を足す
- 理由：工程ごとの資料を自分でも Notion で見返せるようにしつつ、公開リポジトリでも見られるようにした。2か所の内容が食い違わないよう、書く人に合わせて正本を決めた。また、作業記録の状態が「レビュー待ち」のまま残ることが2回続いたため、手順に入れて再発を防ぐ

### TASK-P04 — 計画（段階とタスクの順番）（2026-11-25）
- AI に任せたこと：タスクの洗い出しと依存関係の案、計画の下書き
- 自分で判断したこと：工数・日程は見積もらない／学習カレンダーを MVP に入れる
- 理由：作業量は AI と分担すればこなせる見込みなので、見積もりに時間を使うより、順番と依存関係だけ決めて進めることを優先した。学習カレンダーは、毎日学習できているかが一目で分かり、自分が毎日使い続けるきっかけになるため

### TASK-E03 — 古い構成の名残りを直す（2026-11-25）
- AI に任せたこと：古い構成（FastAPI・Terraform）の名残りの洗い出し（grep）、設定とひな形の修正、JSON の確認、reviewer サブエージェントでの確認
- 自分で判断したこと：使わないものの一覧（CLAUDE.md）と Python の節（.gitignore）は残す／Claude Code の確認・禁止を外す設定は、AI ではなく自分で消す
- 理由：使わない前提の設定が残っていると、読む人が今の構成を誤解するため。AI の権限を緩める変更は、AI 自身にさせずに人が行うほうが安全なため

### TASK-P01 / P02 / P03 — 作り直しと進め方の決め直し（2026-11-21〜25）
- AI に任せたこと：旧資料の読み込みと決定事項の洗い出し（75件）、推奨の判断案、Notion の作り直し、運用ルールと指示文の下書き、Git の運用の解説
- 自分で判断したこと：旧資料は保管して必要な情報だけ引き継ぐ／引き継ぐ決定もタスクにして証跡を作り直す／技術的なことは自分が理解してから決める／重要な判断は自分がする線引き／役割ごとにチャットを分ける／Notion は PM だけが書き、完了報告は progress.md に書く／main は公開用、develop は開発用にし、PR とレビューを通して入れる／ルールの正本を docs/rules.md に置き、Notion には図解版を置く
- 理由：以前の決定を覚えていなかったため、決定と証跡を見える形で作り直したかった。役割と記録の置き場所を決めておけば、どのチャットからでも同じルールで進められる

### TASK-E11 — リポジトリの作り直し（2026-11-20）
- AI に任せたこと：旧リポジトリの状態確認、持ち込むファイルのコピーと記述の修正、公開前チェック（禁止パターンの検索）、最初のコミット
- 自分で判断したこと：旧リポジトリの履歴と v1 の設計記録・証跡は持ち込まず、空のリポジトリから始める／持ち込むのは AI の役割分担と記録ルールの仕組みだけ／v1 の記録が必要になったら、個人的な記述を直してから studai-v1 から移す／コミットのメールは GitHub の noreply にする
- 理由：旧履歴に .env や個人情報が含まれる可能性があり、公開すると取り消せない。基本設計からやり直すため、v1 の設計記録を持ち込む必要もない

### TASK-E08 / P02 / P03 — AI の役割分担と記録ルールの整備（2026-11-19〜20）
- AI に任せたこと：Claude Code の公式ドキュメントの調査、CLAUDE.md・settings.json・reviewer の下書き、記録ルールの案
- 自分で判断したこと：実装は Claude Code、PM・デザイン・レビューは claude.ai のプロジェクトに分ける／Claude Code の「プロジェクト」機能（並列スレッド）は MVP の土台ができるまで使わない／CLAUDE.md を公開リポジトリに含める／記録は必ずローカルとリポジトリに残す
- 理由：週5〜10時間の開発量では並列で動かすより、1タスクずつ理解して取り込むほうが合っている。AI への指示そのものも開発プロセスの記録として見せたい
