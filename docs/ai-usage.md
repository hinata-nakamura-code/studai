# AI の使い方の記録

Studai は Claude を役割ごとに分けて開発しています。このファイルには、AI に任せたことと、自分で判断したことをタスクごとに残します。

## 役割分担（2026-11-20 時点）

| 役割 | 担当 | 設定 |
|------|------|------|
| PM・デザイナー・レビュー | claude.ai のプロジェクト | 指示文はローカルの docs/private/ に保管（非公開） |
| エンジニア（実装） | Claude Code | [CLAUDE.md](../CLAUDE.md)、[.claude/settings.json](../.claude/settings.json) |
| PR 前のレビュー | Claude Code の reviewer サブエージェント | [.claude/agents/reviewer.md](../.claude/agents/reviewer.md) |

- 実装した AI に自分で採点させないよう、レビューは別の文脈（サブエージェント、別のプロジェクト）で行う
- AI が書いたコードは、自分で説明できるようになってから取り込む
- 秘密情報の読み取り禁止や push 前の確認は、指示文ではなく権限設定（settings.json）で強制する

### TASK-E11 — リポジトリの作り直し（2026-11-20）
- AI に任せたこと：旧リポジトリの状態確認、持ち込むファイルのコピーと記述の修正、公開前チェック（禁止パターンの検索）、最初のコミット
- 自分で判断したこと：旧リポジトリの履歴と v1 の設計記録・証跡は持ち込まず、空のリポジトリから始める／持ち込むのは AI の役割分担と記録ルールの仕組みだけ／v1 の記録が必要になったら、個人的な記述を直してから studai-v1 から移す／コミットのメールは GitHub の noreply にする
- 理由：旧履歴に .env や個人情報が含まれる可能性があり、公開すると取り消せない。基本設計からやり直すため、v1 の設計記録を持ち込む必要もない

### TASK-E08 / P02 / P03 — AI の役割分担と記録ルールの整備（2026-11-19〜20）
- AI に任せたこと：Claude Code の公式ドキュメントの調査、CLAUDE.md・settings.json・reviewer の下書き、記録ルールの案
- 自分で判断したこと：実装は Claude Code、PM・デザイン・レビューは claude.ai のプロジェクトに分ける／Claude Code の「プロジェクト」機能（並列スレッド）は MVP の土台ができるまで使わない／CLAUDE.md を公開リポジトリに含める／記録は必ずローカルとリポジトリに残す
- 理由：週5〜10時間の開発量では並列で動かすより、1タスクずつ理解して取り込むほうが合っている。AI への指示そのものも開発プロセスの記録として見せたい
